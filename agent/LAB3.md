# ЛР №3. Контекст и память агента

**Сессии.** Переписка сохраняется в `agent/sessions/<id>.json`. После перезапуска с тем же ID агент загрузил два сообщения и без подсказки назвал имя пользователя (Тимур) и его цель (подготовить защиту ЛР №3).

**Бюджет контекста.** Перед запросом агент оценивает вход: длина JSON с сообщениями и описаниями инструментов, делённая на четыре. История растёт за счёт вызовов инструментов и их результатов. При превышении бюджета `trim` удаляет старые ходы целиком, сохраняя системную инструкцию, текущий ход и связь между вызовом и результатом. Стратегия `summarize` запрашивает у модели краткую сводку без инструментов и помещает её после системной инструкции. Если сводку получить не удалось, применяется `trim`.

**Эксперимент.** При одинаковой начальной истории и бюджете 6000 агенту поручили найти в документации приоритет по умолчанию, добавить две задачи и показать незавершённые. В таблице «до → после» — оценка программы; `prompt_tokens` — фактический вход по данным OpenRouter.

| Стратегия | Шаг и результат | Оценка до → после | `prompt_tokens` |
|---|---|---:|---:|
| trim | 1. Поиск приоритета в документации | 5690 → 5690 | 6742 |
| trim | 2. Усечение; добавлены две задачи | 6044 → 1265 | 1201 |
| trim | 3. Выведены незавершённые задачи | 1687 → 1687 | 1427 |
| trim | 4. Итоговый ответ | 1867 → 1867 | 1904 |
| summarize | 1. Поиск приоритета и просмотр списка | 5690 → 5690 | 6927 |
| summarize | 2. Отдельный запрос сводки | 4827 → 4827 | 4553 |
| summarize | 2. Резервное усечение; модель попросила подтверждение | 6033 → 1254 | 1525 |

Фрагменты [журнала OpenRouter](experiment-live-20261113-191909-000679.txt):

```text
trim:
TRIM: removed=2 before=6044 after=1265

summarize:
SUMMARY: нет места или пустой ответ; переход к trim.
TRIM: removed=2 before=6033 after=1254
```

**Результат.** В режиме `trim` инструмент `search_docs` нашёл в `workspace/docs/tasks.md` приоритет `mid`; два вызова `add_task` создали задачи, а `list_tasks` подтвердил их наличие. В режиме `summarize` все 256 выходных токенов запроса сводки ушли на рассуждение. Текст сводки не был сохранён; после перехода к усечению модель запросила подтверждение и задачи не создала.

В [контрольном прогоне](experiment-offline.txt) с бюджетом 2184 сокращение сработало на пятом шаге: оценка 2222 снизилась до 1260 при усечении и до 1281 при сохранении тестовой сводки. В живом прогоне модели и число действий различались, поэтому по расходу токенов нельзя определить, какая стратегия экономичнее в общем случае.

## Запуск и проверка (Windows PowerShell)

Команды выполняются из корня проекта в настроенном окружении `.venv`. Для запуска агента и эксперимента с OpenRouter нужен ключ в `agent/.env`.

**1. Запустить агента и проверить память между запусками.**

```powershell
.\.venv\Scripts\python.exe agent/agent.py --session lab3-memory-01
```

Сообщите агенту имя и цель, дождитесь ответа и выйдите через `/exit`. Выполните ту же команду с тем же ID и спросите: «Как меня зовут и какая у меня цель?»

**2. Сравнить стратегии на контрольном примере.**

```powershell
.\.venv\Scripts\python.exe -m agent.experiment
```

Запускает `trim` и `summarize` с заранее заданными ответами. Ключ не нужен. На пятом шаге в журнале можно сравнить размер контекста до и после сокращения.

**3. Сравнить стратегии через OpenRouter.**

```powershell
.\.venv\Scripts\python.exe -m agent.experiment --live
```

Обе стратегии получают одну задачу; запись во временную папку подтверждается вводом `y`. Журнал с фактическими `prompt_tokens` сохраняется в UTF-8. Путь к файлу выводится в начале запуска.
